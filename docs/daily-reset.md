# 日次更新の表示と自動受取

## 画面

次回の更新日時は既存メニューに表示します。
クエスト画面を開いている間は、上部に「デイリー更新まで HH:MM:SS」を追加表示します。
残り時間はサーバーから受け取った日時と経過時間で計算し、PCの日付・タイムゾーン設定には依存しません。

表示だけをローカルで更新するため、毎秒サーバーへ問い合わせたり、メニューを開き直したりしません。
カウントが0になると、開いている同じクエスト画面を再取得します。
設定ダイアログや別リソースのUIに切り替えた場合、閉じた画面を勝手に開き直すことはありません。
全クエストがまだ未設定の初回設定画面では、カウントダウンは表示しません。

## 日次の自動受取

毎日JST05:00の日次更新後、**旧日の割当で達成済みかつ未受取(active)**の通常報酬を自動受取します。
全クリア条件を満たした追加20万も対象です。
オンライン中は次の処理タイミング（通常は最大約15秒）で受け取れます。
更新直前の保存待ち時間を先に確定し、直前に達成したクエストも判定します。

オフライン中やサーバー停止中に更新を迎えた分は、元の記録を維持し、次回ログイン後の処理で自動受取します。
オフラインのQboxプレイヤーデータへ直接送金せず、読み込まれたキャラクターを確認してから付与します。
メニューを開く必要はありません。支払いが終わると件数・銀行／現金額を通知します。

次は対象外です。

- 未達成、未提示、リロールで外れたクエスト
- 週次クエスト（これまでどおり期間内の手動受取）
- 受取済み(claimed)、成否確認待ち(pending)
- 自動受取機能を有効にする前に、既に失効していた古い報酬

期間終了後の手動受取APIは引き続き拒否します。自動受取はサーバー内だけの経路です。
期限前の手動受取と更新後の自動受取は同じ記録・条件付き更新を使い、二重配布を防ぎます。
受取額にはその記録に保存済みの金額を使い、過去分を現在の金額へ書き換えません。

## 導入時と再起動

suimag_dailyquest_automation の1行に、自動受取を開始する更新時刻を保存します。
初回起動時の「次の日次更新」から有効になり、再起動・移転後も同じ境界を使用します。
そのため、以前の仕様で既に失効した報酬をまとめて復活させることはありません。
このテーブルもバックアップに含め、開始時刻を意図せず削除・書換しないでください。

自動テーブル作成を無効にしている場合は、更新前に sql/schema.sql を適用してください。
既存の個別報酬・全クリア報酬テーブルは再作成・削除しません。

## 失敗した場合

明確な付与失敗はactiveに戻し、次の自動処理で再試行します。
成否不明の例外・保存失敗はpendingのままにし、自動再配布しません。管理者の照合が必要です。

再試行の間隔は Config.AutoClaim.intervalSeconds（初期30秒）、
1回の処理上限は Config.AutoClaim.batchSize（初期25件）です。
複数期間の残額が多い場合は、数回に分けて受け取ります。
Qboxの金銭保存と当リソースのSQLは同一トランザクションではないため、
強制終了時の厳密なexactly-onceは保証せず、保留記録の照合で対応します。
