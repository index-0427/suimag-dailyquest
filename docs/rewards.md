# 共通報酬

報酬はクエスト個別ではなく、config.lua の Config.Rewards で管理します。

| 報酬 | 初期金額 |
| --- | ---: |
| デイリー1件クリア | 150,000 |
| 当日のデイリー全3件クリア | 追加200,000 |
| ウィークリー1件クリア | 500,000 |

初期の振込先は銀行です。日次は通常3件45万＋全クリア20万で合計65万、週次は2件で合計100万です。
週次の追加全クリア報酬はありません。

## 受取

通常報酬は達成したクエスト、全クリア報酬はデイリー画面の「デイリー全クリア報酬」から手動で受け取ります。
全クリア報酬の条件は**当日の現在の割当3件の進捗がすべて目標に達していること**です。
個別報酬を先に受け取る必要はなく、受取順で総額は変わりません。

交換して外れたクエスト、未提示のクエスト、週次クエストは条件に含めません。
割当数が記録した必要数と一致しない場合も付与しません。
全クリア報酬はキャラクター・日次期間ごとに1回で、JST翌05:00に期限が切れます。
翌日は別の全クリア記録になり、その日のクエストを新たに達成する必要があります。

## 金額変更・旧版からの更新

- Config.Quests の reward は廃止しました。古い個別設定を残すと設定検証で停止するため削除してください。
- 共通設定は account（bank / cash）、daily、dailyComplete、weekly の4項目です。
- 再起動後、キャラクター読込時に当期の未受取（active）の金額を共通設定へ更新します。
- 受取済み（claimed）・成否確認待ち（pending）の金額と状態は変更しません。差額は自動補填しません。
- 更新時点ですでに当日の割当を全クリアしていれば、新しい追加20万を一度受け取れます。
- リロール先の未受取報酬にも現在の共通設定を使います。
- 古い保留記録などを照合できるよう、通常クエスト側の金額スナップショットやアイテム報酬処理は保持します。
- 新テーブル suimag_dailyquest_bonuses が必要です。自動作成が無効なら sql/schema.sql を再適用してください。

## 重複防止と保留対応

通常報酬と全クリア報酬の記録は分かれています。
どちらも active → pending → claimed の条件付き更新で配布し、成否不明ならpendingを維持します。
Qboxの金銭保存と同一のDBトランザクションにはできないため、プロセス強制終了時の厳密なexactly-onceは保証しません。

コンソールの dailyquest_pending は両方を表示し、claim_kind が quest / daily_bonus を区別します。
全クリアの確認番号は bonus:<id>、Qboxの金銭理由は dailyquest:bonus:<id> です。
同じ数値IDの通常報酬とは別物なので混同しないでください。

全クリア報酬の照合対象は suimag_dailyquest_bonuses です。
管理者がリソースを停止し、[通常の保留照合手順](operations.md)と同じように実際の配布記録を確認してから、
**対象のIDとcitizenidを指定した1行だけ**をclaimed、または未配布と確認できた場合のみactiveに戻します。
未確認の一括解除・自動再配布は行いません。
