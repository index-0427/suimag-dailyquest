# 共通報酬

報酬はクエスト個別ではなく、config.lua の Config.Rewards（金銭）と Config.CoinRewards（追加コイン）で管理します。

| 報酬 | 初期金額 |
| --- | ---: |
| デイリー1件クリア | 150,000 |
| 当日のデイリー全3件クリア | 追加200,000 |
| ウィークリー1件クリア | 500,000 |

初期の振込先は銀行です。日次は通常3件45万＋全クリア20万で合計65万、週次は2件で合計100万です。
週次の追加全クリア報酬はありません。

## タグ別の追加コイン

| タグ | デイリー | ウィークリー |
| --- | --- | --- |
| 犯罪（crime） | 150,000＋黒コイン1枚（black_coin） | 500,000＋黒コイン3枚（black_coin） |
| 職業・所属必須（employment） | 150,000＋白コイン1枚（white_coin） | 500,000＋白コイン3枚（white_coin） |

現行の対象は家強盗・ブースティング・ATM強盗・コンビニ強盗・カーゴ強盗（黒）と勤務（白）です。Urideはタグなしです。タグなしのクエストと全クリア追加報酬にはコインを付けません。
コインの種類・枚数は金銭と同じ進捗レコードに保存します。画面にも金銭とコインを併記し、日次の自動受取でも付与します。
`Config.CoinRewards` の daily=1、weekly=3、crime='black_coin'、employment='white_coin' で設定します。

## 受取

通常報酬は達成したクエスト、全クリア報酬はデイリー画面の「デイリー全クリア報酬」から手動で受け取ります。
全クリア報酬の条件は**当日の現在の割当3件の進捗がすべて目標に達していること**です。
個別報酬を先に受け取る必要はなく、受取順で総額は変わりません。

交換して外れたクエスト、未提示のクエスト、週次クエストは条件に含めません。
割当数が記録した必要数と一致しない場合も付与しません。
全クリア報酬はキャラクター・日次期間ごとに1回です。JST翌05:00以降、達成済みの未受取分は通常の日次報酬とともに自動受取します。
オフライン中の分は記録を保持し、次回ログイン時に受け取ります。週次は期限内の手動受取が必要です。
自動受取の開始範囲と障害時の扱いは [日次更新](daily-reset.md) を参照してください。
翌日は別の全クリア記録になり、その日のクエストを新たに達成する必要があります。

## 金額変更・旧版からの更新

- Config.Quests の reward は廃止しました。古い個別設定を残すと設定検証で停止するため削除してください。
- 共通設定は account（bank / cash）、daily、dailyComplete、weekly の4項目です。
- 再起動後、キャラクター読込時に当期の未受取（active）の金額を共通設定へ更新します。
- 受取済み（claimed）・成否確認待ち（pending）の金額と状態は変更しません。差額は自動補填しません。
- 更新時点ですでに当日の割当を全クリアしていれば、新しい追加20万を一度受け取れます。
- リロール先の未受取報酬にも現在の共通設定を使います。
- 金額とコインのスナップショットを保持します。当期activeは設定に合わせて更新し、pending・claimedと期限切れの記録は変更しません。
- 旧版のアイテム単体報酬には対応しません。追加コインとは別の仕組みです。
- progressにreward_coinとreward_coin_amountを追加します。自動作成が無効なら更新前にschema.sqlを適用してください。既存記録の初期値はコインなしです。
- suimag_dailyquest_bonuses と suimag_dailyquest_automation が必要です。自動作成が無効なら sql/schema.sql を再適用してください。

## 重複防止と保留対応

通常報酬と全クリア報酬の記録は分かれています。
どちらも active → pending → claimed の条件付き更新で配布し、成否不明ならpendingを維持します。
追加コインが未登録・持ち物が満杯なら金銭を付与せずactiveに戻します。日次の自動受取は空きができた後に再試行します。
金銭を先に付与し、成功後にコインを付与します。途中で失敗・切断・結果不明になった場合はpendingを維持し、二重配布を防ぎます。
管理者は金銭とコインそれぞれの付与ログを照合し、不足分だけを補填してください。金銭付与済みの記録をactiveに戻すと二重配布になるため、報酬全体を再試行しないでください。
Qboxの金銭保存と同一のDBトランザクションにはできないため、プロセス強制終了時の厳密なexactly-onceは保証しません。

コンソールの dailyquest_pending は両方を表示し、claim_kind が quest / daily_bonus を区別します。
全クリアの確認番号は bonus:<id>、Qboxの金銭理由は dailyquest:bonus:<id> です。
同じ数値IDの通常報酬とは別物なので混同しないでください。

全クリア報酬の照合対象は suimag_dailyquest_bonuses です。
管理者がリソースを停止し、[通常の保留照合手順](operations.md)と同じように実際の配布記録を確認してから、
**対象のIDとcitizenidを指定した1行だけ**をclaimed、または未配布と確認できた場合のみactiveに戻します。
未確認の一括解除・自動再配布は行いません。
