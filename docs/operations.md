# 運用と受入確認

## 対象環境への導入

この手順は管理者が承認後に行う作業です。本リポジトリの実装作業からは実行していません。

1. 現行の起動設定とDBをバックアップする。旧バトルパスのデータは削除しない。
2. `suimag-dailyquest` をリソースディレクトリに配置し、使用する実装ブランチ／コミットをチェックアウトする。
   サーバーの `resources` 直下にあるGitリポジトリではGitコマンドを実行しない。
   リソースの独立したGitリポジトリを作る場合も、そのディレクトリ内でのみ操作する。
3. 依存4リソースを確認し、`suimag-dailyquest` を起動する。DB権限は専用10テーブルの作成・読書きに必要。
   自動作成を無効にする場合は先に `sql/schema.sql` を適用する。
4. コンソールの `Ready. Command: /dailyquest` を確認する。DB初期化エラー時は30秒ごとに再試行し、その間の報酬は無効。
5. 次の受入確認を行う。設定の報酬額は実運用前に調整する。

## ゲーム内の受入確認

| 操作 | 期待結果 |
| --- | --- |
| キャラクターで接続し /dailyquest | 初回は属性設定、保存後は日次3件・週次2件と更新時刻を表示 |
| 提示されたクエストを達成して報酬をクリック | 設定された報酬を付与し、受取済みになる |
| 連打、再表示、再接続後に同じ報酬を操作 | 再配布しない |
| 15秒以上接続し一覧を更新 | 滞在クエストに進捗。分表示は切り捨て |
| water / burger を使用 | 使用完了1回につき日次・週次へ+1、3秒未満の重複は無視 |
| 使用キャンセル、他アイテム | 加算しない |
| キャラクターを切り替える | 別の進捗・報酬状態。旧メニューは閉じる |
| メニュー取得／受取の途中で切断する | 新しい接続者へ配布しない。成否不明は保留 |
| リソースを再起動 | 保存済み進捗・受取状態を保持 |
| JST 05:00をまたぐ | 新しい日次クエスト。古い画面の受取は拒否 |
| 月曜 JST 05:00をまたぐ | 日次・週次とも更新。参加日数は新週で1 |
| 同じ活動の完了通知をクールダウン内に再送 | 追加加算しない |
| 旧バトルパスが起動中・起動準備中 | メニュー表示・進行・手動受取・自動受取を継続 |
| クライアントから任意の進捗付与を試行 | 公開された進捗付与ネットイベントがない |

日付境界のために共有テスト鯖のOS時計を変えないでください。
期間計算と同時処理はローカル自動テストでも検証できます。
障害注入（DB停止など）は共有サーバーを巻き込まない隔離環境で実施します。

## 保留報酬の照合

コンソール専用の `dailyquest_pending` で保留中の最大50件を表示します。
プレイヤーから実行しても情報は返しません。

1. claim_kind、確認番号、citizenid、quest_id、時刻、報酬を控える。通常はprogress.id、daily_bonusはbonuses.idで照合する。
2. このリソースを停止し、処理中の受取がない状態にする。
3. 当リソースの `Claim <id> reserved` / `reward provider returned success` と、
   Qboxの金銭理由 `dailyquest:<id>`（全クリアは `dailyquest:bonus:<id>`）、`money delivered` / `coins delivered` のログとインベントリの記録を照合する。
   プロバイダーが成功を返したログだけでは、強制終了直前の永続化完了を保証できない。
4. 配布済みが確認できたものだけ、対象の1行を `claimed` にする。
5. 金銭・コインとも未配布と確認でき、期間内なら対象の1行を `active` に戻して本人に再受取してもらう。金銭のみ付与済みの場合は不足したコインだけを補填してclaimedにし、全体を再試行しない。
   自動受取対象の日次は、期限後でもactiveに戻すと次のログイン／処理時に再試行する。週次・導入前の失効分は自動受取しないため、必要に応じて管理者が補填して記録する。
6. 判断できない場合は保留を維持する。一括解除しない。

以下は通常クエストのSQL例です。全クリア報酬は [共通報酬](rewards.md) の対象テーブルを使ってください。

SQL例（`123` を確認したID、`CONFIRMED_CITIZENID` を確認したcitizenidに置換）:

```sql
-- まず対象を確認。以下は本番DBへの操作なので承認とバックアップの上で実施。
SELECT * FROM suimag_dailyquest_progress
WHERE id = 123 AND citizenid = 'CONFIRMED_CITIZENID' AND status = 'pending';

-- 配布済みと確認した場合のみ:
UPDATE suimag_dailyquest_progress
SET status = 'claimed', claimed_at = UNIX_TIMESTAMP()
WHERE id = 123 AND citizenid = 'CONFIRMED_CITIZENID' AND status = 'pending';

-- 未配布と確認し、期限内で本人が再受取する場合のみ（上のUPDATEとの二者択一）:
UPDATE suimag_dailyquest_progress
SET status = 'active', attempted_at = NULL
WHERE id = 123 AND citizenid = 'CONFIRMED_CITIZENID'
  AND status = 'pending' AND ends_at > UNIX_TIMESTAMP();
```

## バックアップとロールバック

- 専用10テーブルと設定を通常のDBバックアップに含める。
- 自動データ削除は行わない。クールダウンの記録もバックアップに含める。
- ロールバックはこのリソースの起動指定を外し、停止する。専用テーブルは保持してよい。
- 旧バトルパスを戻す場合は新リソース停止後に戻し、報酬の二重運用を避ける。
- 当リソースは起動／停止で既存リソースの設定・DBを変更しない。受取済み金銭は停止しても取り消さない。

## 自動検証の範囲

- Lua構文、設定値検証、JSTの日次・週次境界、複数年・別ホストタイムゾーン
- 時間の期間分割、ストール／時計の変化／タイマー巻戻り
- 同時受取、キャラクター切替、ログアウト中の猶予時間、未知の受取結果、DB失敗
- クライアントの受取可否、エラー、古い応答の破棄、他リソースのメニューを閉じないこと
- 実MariaDBによる同時UPDATE、目標の固定、未受取の共通報酬更新と受取済み／保留金額の保護、トランザクションロールバック、活動通知の永続クールダウン

FiveMランタイム、ゲーム内NUI・ox_lib表示、実際のQbox／ox_inventoryの副作用はモックでは完全再現できません。
そのため自動テスト成功とゲーム内確認済みを区別します。

## 48件版の追加受入確認

- 自動テーブル作成が無効の既存環境は schema.sql を適用し、signal_gates / preferences / boards / assignments テーブルを追加する。
- 徒歩・自転車・自動車をそれぞれ運転し、約15秒後の更新で該当する距離だけ増えること。
- 同乗、バイク、航空機、車両乗換、バケット変更、死亡、瞬間移動では距離を加算しないこと。
- 出勤・退勤・職業切替で勤務時間が切り替わり、無職では加算しないこと。
- 抽選された活動を実施し、提示中の該当クエストだけ加算されること。未提示の活動は加算しないこと。
- 魚・カニの売却を計上し、宝石売却は計上しないこと。
- ATM・コンビニ強盗で黒いお金を獲得すると加算し、満杯・部品取得・他人からの譲渡では加算しないこと。
- satou_logging停止時はATM・コンビニが新規抽選から外れ、提示済み・デバッグ一覧には連携元未起動と表示すること。
- Urideは運転手への通常送迎・NPCミッションの精算で加算し、乗客利用では加算しないこと。
- 給与・通常送金・クエスト報酬の入金だけで仕事系が進まないこと。
- 家強盗の放棄／時間切れでは進まず、成功時は参加者ごとに1回だけ進むこと。
- カーゴ契約の成功時に通知内の参加者へ1回ずつ加算し、他のlunar契約・途中のアイテム取得では加算しないこと。
- リソース再起動・午前5時更新の直後でも、直前の同活動通知のクールダウンが維持されること。
- 連携元を停止すると未達成項目に「連携元が未起動」と表示し、既に達成した報酬は受け取れること。

通知に一意IDのない旧連携はクールダウンによる抑止です。クールダウン後の古い通知再送を完全には識別できません。
既存の資材を更新した場合は通知契約と入金理由を再確認してください。

## 抽選・属性・リロールの追加確認

- 初回設定をキャンセルすると抽選も加算も始まらない。保存後の日次は3件、週次は2件。
- 犯罪除外で家強盗・ブースティング・ATM強盗・コンビニ強盗・カーゴ強盗が出ない。職業必須除外／無職では勤務が出ない。
- 日次に短時間枠が1件以上あり、同期間の表示枠に重複がない。
- 属性を変更しても提示中の内容・進捗・交換回数は変わらない。
- 未達成1件を交換すると0から始まり、日次と週次の残り回数が独立して減る。
- 達成済み・受取済み・保留中は交換できない。確認画面のキャンセルでも回数は減らない。
- 再接続・リソース再起動後も同じ抽選結果と交換回数を保持する。
- 日次更新で日次だけ、週次更新で週次の交換権が復活する。
- 古い画面の交換要求・未提示IDの受取要求は拒否する。
- 候補不足でも除外を無視しない。設定画面へ戻って変更でき、リロール権は消費しない。

## 共通報酬の追加確認

- 全デイリーの表示と入金額が1件15万、全ウィークリーが1件50万であること。
- 当日の3件が未達成なら、全クリア20万を受け取れないこと。
- 全3件を達成すると専用項目から20万を1回だけ受け取れ、通常分と合わせて65万になること。
- 個別報酬と全クリア報酬は別々に受け取れること。受取順に依存しないこと。
- 同時操作・再接続・再起動で全クリア報酬を再配布しないこと。
- 翌日は新しい3件の達成が必要で、前日の達成では全クリア報酬を受け取れないこと。
- 更新時は未受取分だけ新金額に変わり、受取済み・保留中の金額と状態は変わらないこと。

## 日次更新・カウントダウンの追加確認

- クエスト画面を開くと、次回日次更新時刻と秒単位の残り時間を表示する。
- 画面を閉じる、設定ダイアログを開く、別リソースのメニューを開くとカウントダウンが消える。
- カウントダウン表示中にメニューの点滅やフォーカス移動がないこと。
- 更新時刻を迎えると、開いている同じクエスト画面だけを更新する。閉じた画面は開き直さない。
- 達成済みの日次報酬・全クリア報酬は、画面を開いていなくても更新後に自動受取する。
- オフライン／サーバー停止中に更新を越えた達成分は、次回ログイン時に自動受取する。
- 未達成・交換済み・週次・保留中・受取済みを自動配布しないこと。
- 手動受取との競合、再接続、再起動で二重配布しないこと。
- 自動受取開始境界は再起動しても変わらず、導入前の失効分を遡って配布しないこと。

## 追加コインの受入確認

- black_coinとwhite_coinをox_inventoryに登録し、progressの追加2列を適用する。
- 家強盗・ブースティング・ATM強盗・コンビニ強盗・カーゴ強盗は黒、勤務は白を、日次1枚・週次3枚受け取れること。
- タグなしと全クリア追加報酬にコインが付かないこと。
- 満杯・未登録なら金銭も付与されず、空き確保・登録後に再受取できること。
- 日次更新時の自動受取でもコインが入り、再接続・再受取で増殖しないこと。
