# クエストGUI

F10、`/dailyquest`、`OpenQuests()` exportで専用NUIを開きます。
デイリー／ウィークリーの切替、進捗、受取状態、リロール残数、全クリア報酬、日次更新までの残り時間を表示します。
Escまたは右上の×で閉じ、ゲームへ入力を戻します。狭い画面ではカードを縦に並べてスクロールできます。

抽選設定とリロール確認は既存のox_libダイアログを使います。設定を保存・キャンセルした後はボードへ戻ります。
GUIからは操作名とクエストIDだけを送り、クライアントが直前のサーバー応答から期間・受取条件を確認します。
最終的な報酬・交換・抽選の検証は従来のサーバー処理が行います。
通信中は操作を抑止し、Escと閉じるボタンは使えます。閉じた後やキャラクター切替後の応答は画面を再表示しません。

移行中に旧ox_libメニューへ戻したい場合は、`config.lua` に `Config.UseContextMenu = true` を追加します。
省略またはfalseで専用GUIを使用します。外部CDN、フロントエンドビルド、追加ランタイム依存はありません。

## ブラウザで見る

リポジトリのルートで実行し、`http://127.0.0.1:8765/preview.html` を開きます。

```bash
python3 -m http.server 8765 --bind 127.0.0.1 --directory ui
```

プレビューはサンプルデータです。期間切替・受取済み表示・閉じる・再表示を試せます。
抽選設定とリロール確認のダイアログはゲーム内で確認してください。
`preview.html` と `preview.js` はfxmanifestに含まれず、FiveMへ配信されません。

## 検証

```bash
lua tests/client_spec.lua  # 旧メニューの互換性
lua tests/gui_spec.lua     # 操作、入力フォーカス、期限更新、遅延応答
node --check ui/quests.js
node tests/countdown_spec.js
```

PlaywrightとChromiumがある環境では `node tests/gui_browser_spec.js` も実行できます。
ブラウザのパスは `CHROMIUM_PATH` で指定でき、初期値は `/usr/bin/chromium` です。
この検証は一時的なローカルHTTPサーバーを起動し、終了時に閉じます。

実機では以下を確認します。

- F10／コマンドで開き、マウス・キーボード操作とEscでの入力返却を確認。
- 初回抽選、設定変更、リロールの確定と取消、通常報酬と全クリア報酬の受取。
- 受取済み・確認待ち・連携元停止状態の表示、ウィークリーの期限案内。
- 日次更新をまたいだときの表示更新、通信中に閉じる、キャラクター切替、リソース停止。
- 他リソースのNUIと同時に開く運用がある場合の入力フォーカス。

## 複数エージェントでの作業

各エージェントに別ブランチ・別worktreeを割り当てます。同じフォルダでブランチだけを切り替えてもファイルは共有されます。
UI担当は `ui/` と `client/main.lua`、サーバー担当は `server/` と `sql/` のように担当を事前に決めます。
`fxmanifest.lua`、README、CIなど双方が触りやすいファイルは、統合担当が差分を確認して順番に取り込みます。

このGUIの作業ブランチは `feat/quest-gui` です。統合する際は、対象ブランチの未コミット変更を片付けてからGUIのコミットをcherry-pickし、
他エージェントの変更と合わせて上記テストを再実行してください。worktreeの分離は上書きを防ぎますが、統合時の競合を完全にはなくしません。
