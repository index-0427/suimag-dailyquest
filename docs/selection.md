# 抽選・属性設定・リロール

## 初回

初めて /dailyquest を開いたときは設定画面を提示します。
「犯罪を除外」「職業・所属必須を除外」のチェックを保存すると、そのキャラクターの日次3件・週次2件を抽選します。
設定をキャンセルした場合、抽選・進捗・報酬は始まりません。初期表示では犯罪を除外するチェックが入っています。

| 属性 | 初期カタログでの対象 |
| --- | --- |
| 犯罪 | 家強盗・ブースティング |
| 職業・所属必須 | Qboxで職業に就いて行う勤務 |
| 一般 | 上記以外。無所属でも参加できる仕事を含む |

属性は複数付与できます。企業系を許可しても、実際の所属・職種・最低ランクが合わないクエストは抽選しません。
連携元リソースが started でない活動も新しい抽選から除外します。

## 日次・週次

- 日次候補20件から3件、週次候補20件から2件をサーバーで抽選します。同じ期間内の提示枠は重複しません。
- 日次には短時間枠を最低1件含めます。初期設定では来訪・飲食・徒歩・自転車に短時間タグを付けています。
- 日次はJST毎日05:00、週次はJST月曜05:00に切り替わります。
  新しい期間の抽選は、そのキャラクターが接続して処理対象になったときに行います。オフライン中の期間は抽選しません。
- 日次と週次の同じ活動は同時に選ばれ得ます。その場合は1回の活動が両方の進捗になります。
- 抽選結果はDBに保存し、画面を開き直す、再接続する、リソースを再起動する操作では変えません。
- 提示されていないクエストには進捗・報酬を付与しません。抽選前の行動を後から加算しません。
- 参加日数は選ばれた日から数えます。初回抽選の当日は1日として数えます。
  参加日数や時間の目標を残り期間内に達成できない場合は抽選しません。

## 設定の変更

メニューの「抽選する属性を設定」からいつでも変更できます。
保存した新しい設定は、次の通常抽選とリロールに適用します。
既に提示したクエスト、その進捗、リロール回数は変わりません。

所属変更・連携元の停止でも、自動で別のクエストに交換しません。
仕事に参加できなくなった場合も、未達成なら残りのリロールを使って交換できます。
達成済みの報酬は連携元が停止しても受け取れます。

## リロール

- 日次は1日1回、週次は週1回。それぞれ独立した権利です。
- 任意の**未達成クエスト1件**を選び、進捗を失うことを確認して交換します。
- 達成済み、受取済み、報酬処理中・確認待ちは交換できません。
- 交換後の進捗は0です。元のクエスト、ほかの表示枠、同期間で一度提示したクエストは交換先になりません。
- 最新の除外設定、現在の所属条件、リソース稼働状態を使います。
- 日次の唯一の短時間枠を交換する場合は、交換後も短時間枠を維持します。
- 来訪・参加日数クエストは交換先にしません。過去のログインを交換直後の達成に使うことを防ぎます。
- 候補が足りない場合は理由を表示し、元のクエストと残り回数を維持します。除外設定を無視した補充はしません。
- 交換処理・進捗の初期化・回数消費は1つのSQLトランザクションです。同時送信や再送で回数を増やせません。
- 午前5時をまたいだ古い画面のリロール・受取は拒否します。画面を更新してください。

## 設定の拡張

`config.lua` の末尾で各定義に属性と条件を付けています。

```lua
quest.tags = { employment = true }
quest.requirements = {
    employed = true,
    jobs = { police = 2 }, -- 主職がpolice、最低ランク2
    types = { leo = true }, -- 指定した場合は職種条件も必要
}
quest.quick = false
```

所属条件はQboxの主職 PlayerData.job を参照します。退勤中でも、所属条件を満たしていれば抽選できます。
勤務の進捗には出勤状態が必要です。
所属条件を付けた定義は employment タグを必須にし、設定検証で抜けを検出します。

`Config.Draw = { daily=3, weekly=2 }` が提示数です。
一般向け・連携不要の候補と短時間枠を十分に残してください。
条件に合う候補が必要数未満なら、誤った属性を出さずエラーで待機します。

## 既存版からの更新

抽選用の preferences / boards / assignments と全クリア報酬用の bonuses を含め、自動受取開始時刻の automation を含め専用テーブルは合計8つです。
AutoCreateTables=trueなら起動時に追加します。無効なら sql/schema.sql を再適用してください。
既存テーブル・既存の受取状態は削除しません。

初回の属性設定後、既存版で進捗があるクエストが通常抽選に選ばれた場合は、その進捗・目標・受取状態を引き継ぎます。未受取の報酬額は共通設定に更新し、受取済み・保留中の金額は維持します。
選ばれなかった古い記録は表示・加算・受取の対象外です。保留報酬は管理者用の確認一覧に残ります。
リロール先だけは進捗0にし、既存版で受取済み・確認待ちのクエストを交換先にしません。

更新は可能なら週次更新時刻に合わせ、更新後のキャラクターに初回設定を案内してください。

全クリア報酬は現在提示中のデイリー全件が対象で、交換済み・未提示・週次クエストの達成は数えません。[報酬仕様](rewards.md)を参照してください。

日次更新では新しい抽選とともに、旧日の達成済み未受取報酬を自動受取します。週次の受取期限は変わりません。[日次更新の詳細](daily-reset.md)。
